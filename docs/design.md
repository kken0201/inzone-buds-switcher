# 設計書 — inzone-buds-switcher

## 1. 目的

Sony INZONE Buds（WF-G700N）を USB ドングルで使っているときに、

- イヤホンを**ケースから出して接続されたら**、指定した出力デバイス（INZONE Buds - Game）に Windows の既定の出力を切り替える
- **ケースに戻して切断されたら**、指定した出力デバイス（スピーカー等）に戻す
- 切り替え時に通知を出す
- システムトレイに左右イヤホン・ケースのバッテリー残量を表示する

常駐アプリを作る。

## 2. 要件

| 区分 | 内容 |
|---|---|
| 対象 OS | Windows 11 のみ（Windows 10 は考慮しない） |
| 対象機器 | INZONE Buds の USB トランシーバー（VID `054C` / PID `0EC2`） |
| 言語 | Rust |
| 配布 | ランタイム不要の **exe 1 つ**。ダウンロードしてダブルクリックするだけで使える |
| 非目標 | Bluetooth / LE Audio 接続時の対応、他の INZONE 製品、macOS / Linux |

## 3. 全体構成

```
┌──────────────────────── 1 プロセス（常駐） ───────────────────────┐
│                                                                    │
│  [HID 監視スレッド]  ──(Event)──▶  [メインスレッド: Win32 メッセージループ] │
│   Win32 HID API でドングルを読む     ├ 状態機械（接続/切断の判定・デバウンス） │
│   ・状態レポート(接続/切断)          ├ 出力切り替え（Core Audio / COM）      │
│   ・バッテリーレポート                ├ トレイアイコン・メニュー             │
│   ・ドングルの抜き差し追従            ├ 通知                                │
│                                      └ 設定の読み書き                       │
└────────────────────────────────────────────────────────────────────┘
```

- HID の読み取りはブロッキングなので専用スレッドで行い、`std::sync::mpsc` でメインスレッドにイベントを送る
- トレイアイコンと COM（オーディオ）はメインスレッド（STA）で扱う。メインスレッドは Win32 のメッセージループで待つ
- メッセージループを起こすため、転送スレッドを 1 つ挟む。監視スレッドからのイベントをメインスレッド用のチャネルに入れ直し、`PostMessageW` で独自メッセージ（`WM_APP`）を送る。受け取ったウィンドウプロシージャがチャネルを空になるまで読む。監視スレッドを Win32 のウィンドウに依存させず、`watch` サブコマンドと同じ形で使えるようにするため
- デバウンスの確定待ちは `SetTimer` で、状態機械が返す確定時刻に合わせて起こす
- メッセージを受けるウィンドウは表示しない通常のウィンドウにする。メッセージ専用ウィンドウ（`HWND_MESSAGE`）には、Explorer の再起動を知らせる `TaskbarCreated` のブロードキャストが届かないため

## 4. 各機能の設計

### 4.1 接続/切断の検知（HID）

詳細は [protocol.md](protocol.md)。要点：

- ドングルは接続状態が変わると**自発的に状態レポートを送る**（buds-watcher の解析結果）
- 左右それぞれの接続フラグが取れる
- 起動直後の初期状態は、問い合わせ `41 02` の応答（左右の接続フラグ）で取得する。両耳ともケース内だとドングルは応答しないので、送信できたのに 3 秒以内に応答がなければ、両耳とも切断とみなす。Unknown のままにすると、ケース内で起動してから取り出したときに「Unknown から決まった」扱いになり、切り替わらないため。送信がタイムアウトしたとき（[protocol.md](protocol.md) 7 章の状態）は Unknown のままにする
- HID の読み書きは hidapi を使わず、Win32 API（cfgmgr32 / hid.dll / ReadFile・WriteFile）を直接呼ぶ。hidapi は列挙・初期化のときに文字列ディスクリプタを要求するが、ドングルがこれに応答しなくなることがあり、そのあいだ処理が止まるため（[protocol.md](protocol.md) 7 章）
- 問い合わせの送信にはタイムアウトを付ける。同じ理由で、送信が戻らないことがあるため
- 接続/切断は、自発送信の状態レポート `12 01` で検知する。加えて、30 秒ごとにバッテリーを問い合わせ（`41 04`）、左右の値が `0xFF` かどうかでも接続状態を確かめる。状態レポートが届かないことがあり、取りこぼしても追いつけるようにするため（[protocol.md](protocol.md) 1 章）。両耳ともケース内のときは応答がないので、起動直後の `41 02` を除き、応答がないことだけを理由に状態を変えない
- 問い合わせへの応答は INZONE Hub など、ほかのアプリの要求に対するものも届く。種別とシーケンス番号で自分の要求への応答かを判定する。自分のシーケンス番号は 0x80〜0xFF を使い、Hub（小さい番号）と重なりにくくする
- ドングルが抜かれたら（読み書きが `ERROR_DEVICE_NOT_CONNECTED` で失敗したら）ハンドルを閉じ、3 秒ごとに再列挙して復帰を待つ。スリープからの復帰では開き直さなくてよい

### 4.2 状態機械

```
          どちらか接続 (デバウンス後)
  ┌────────────┐ ───────────────────▶ ┌────────────┐
  │ Disconnected│                      │ Connected  │
  │ (両方切断)  │ ◀─────────────────── │ (片方以上)  │
  └────────────┘   両方切断 (デバウンス後) └────────────┘
         ▲
         │ ドングル未検出 / 初期状態不明 → Unknown（切り替えない）
```

- **接続の定義**：左右どちらか一方でも接続されたら Connected（片耳運用に対応）
- **デバウンス**：変化が約 1〜2 秒続いたら確定する。両耳を順番に取り出す/しまう間のバタつきを防ぐ
- **Unknown では切り替えない**：起動直後やドングルが抜かれたときに、誤って出力を変えないため
  - Unknown から Connected / Disconnected に決まったときも切り替えない。切り替えるのは Disconnected と Connected の間の変化だけ。起動直後やドングルを挿し直した直後は、直前の状態が分からず「変化した」とは言えないため
  - Unknown から決まるときもデバウンスする。判定の経路を 1 つにするため
- **ドングルを失ったら、デバウンスせずすぐ Unknown にする**。確定待ちの変化も捨てる。ドングルがない間に届いた観測は当てにならないため
- **接続の観測**：状態レポート（`12 01`）、接続の問い合わせの応答（`14 02`）、バッテリーの応答（`14 04`。左右の値の有無）のどれも使う
- 状態機械は純粋なロジックにして、時刻を引数で渡す形で単体テストする

### 4.3 出力デバイスの切り替え

- 列挙：Core Audio の `IMMDeviceEnumerator::EnumAudioEndpoints(eRender, DEVICE_STATE_ACTIVE)`
- 現在の既定：`GetDefaultAudioEndpoint(eRender, eConsole)`
- 既定の設定：非公開 COM インターフェイス **`IPolicyConfig::SetDefaultEndpoint`** を使う
  - 公開 API には既定デバイスを変える手段がない。SoundSwitch や EarTrumpet なども同じ方法を使っており、事実上の定番
  - `eConsole` と `eMultimedia` を設定する。`eCommunications`（通話用）も変えるかは設定で選べるようにする
- デバイスは**エンドポイント ID**（`{0.0.0.00000000}.{GUID}` 形式の安定した文字列）で保存する。表示名は表示用に保存する
- ドングルのデバイス（「INZONE Buds - Game」「INZONE Buds - Chat」）は、エンドポイントを提供する USB インターフェイスのインスタンス ID（プロパティ `{b3f8fa53-0004-438e-9003-51a46e139bfc},2`）に含まれる VID/PID（`VID_054C&PID_0EC2`）で見分け、末尾の `MI_03` が Game、`MI_00` が Chat。エンドポイント自身のインスタンス ID には VID/PID が入らない。接続時の切り替え先は Game を想定する

#### 切断時の戻し先

戻し先は**設定された 1 つのデバイスだけ**で、切り替えのたびに推測し直すことはしない。動きを予測しやすくするため。

- **初期値は自動で覚える**：戻し先が未設定のまま初めて Connected になったとき、切り替える直前の既定デバイスを戻し先として保存し、通知で知らせる
  - その既定デバイスがドングルのデバイスだった場合は保存しない（未設定のまま）
- **変更はトレイメニューで行う**：一覧から選ぶか、「今の出力を切断時の出力にする」で現在の既定デバイスを設定する。どちらもドングルのデバイスは選べない

#### 切断時に切り替えない条件

次のどれかに当てはまるときは切り替えず、必要に応じて通知だけ出す。既定デバイスがドングルのデバイスかどうかを最初に見る。利用者が手動で出力を変えたのなら、戻し先が未設定でも警告する必要がないため。

| 条件 | 通知 |
|---|---|
| 戻し先が未設定 | ⚠ 切断時の出力が未設定です |
| 戻し先のデバイスが存在しない（USB スピーカーが抜かれている等） | ⚠ 戻し先のデバイスが見つかりません |
| 切断時点の既定デバイスがドングルのデバイスではない（接続中に利用者が手動で出力を変えた）。既定デバイスがない場合も含む | なし |

接続時は、接続時の出力（未設定ならドングルの Game デバイス）が再生デバイスの中にないとき切り替えない。`auto_switch` がオフのときは、接続/切断の状態だけを追い、切り替えも戻し先の自動設定もしない。

### 4.4 システムトレイ

- アイコン：接続中/切断中/ドングル未検出の 3 状態で見た目を変える
  - 接続中は緑の円、切断中は灰色の円、状態が分からないとき（ドングル未検出、ドングルはあるが接続状態の確認中）は灰色の輪。形と色の両方を変え、色を見分けにくくても区別できるようにする
  - 中間の明るさの色にして、ダーク・ライトどちらのタスクバーでも見えるようにする
  - 実行時に描く（`CreateIconIndirect`）。アイコンのファイルを持たずに exe 1 つで済ませるため
- ツールチップ：`INZONE Buds  L 80% / R 75% / C 60%`（不明な値は `--`）
  - ドングルが外れたら残量を消す。ケースに戻した側の残量も消す。次の問い合わせ（最大 30 秒後）まで古い値が残るのを避けるため
- 左クリック・右クリックのどちらでもメニューを開く
- 右クリックメニュー：

```
INZONE Buds: 接続中
L 80% / R 75% / ケース 60%
──────────────
✓ 自動切り替え
  接続時の出力   ▶ (再生デバイス一覧)
  切断時の出力   ▶ (再生デバイス一覧)
  今の出力を切断時の出力にする
✓ 切り替えを通知
✓ バッテリー低下を通知
  Windows 起動時に開始
──────────────
  ログフォルダを開く
  終了
```

- 1 行目の状態は「接続中」「切断中」「確認中」「ドングル未検出」のどれか。2 行目は残量。どちらも選べない項目として表示する
- 「接続時の出力」はすべての再生デバイスを並べ、設定されたデバイス（未設定ならドングルの Game）に印を付ける
- 「切断時の出力」はドングルのデバイスを並べない（[4.3](#切断時の戻し先)）
- 設定されたデバイスが再生デバイスの中にないときは、「（見つかりません）」を付けて選べない項目として印付きで表示する。設定が残っていることが分かるようにするため
- 「今の出力を切断時の出力にする」は、既定のデバイスがドングルのデバイスのとき（または既定のデバイスがないとき）は選べない
- 再生デバイスはメニューを開くたびに列挙し直す。抜き差しされたデバイスを反映するため
- メニューで設定を変えたら、すぐに設定ファイルに保存する
- メニューを開いている間も HID のイベントは処理し続ける
- 設定画面（ウィンドウ）は作らない。設定はすべてトレイメニューで完結させる

### 4.5 通知

- トレイアイコンの **バルーン通知**（`Shell_NotifyIcon` + `NIF_INFO`）を使う
  - Windows 11 ではトースト通知として表示される
  - AppUserModelID の登録やショートカット作成が不要で、exe 単体配布と相性がよい
  - WinRT のトースト通知は使わない。AUMID を HKCU に登録する処理が必要になり、単体配布の手軽さが損なわれるため
- 全画面のゲーム中は Windows が通知を抑止するため、表示されない（既知の制約）

#### 通知の種類

通知は「切り替え」と「バッテリー」の 2 種類に分け、トレイメニューで別々にオン/オフできる。ただし ⚠ の警告は、期待した切り替えが起きなかったことを知らせるもので、見逃すと原因が分からなくなるため、オフにしていても常に表示する。

| 種類 | 場面 | 文面の例 |
|---|---|---|
| 切り替え | 接続して出力を切り替えた | 🎧 INZONE Buds に切り替えました |
| 切り替え | 切断して出力を戻した | 🔈 スピーカーに戻しました |
| 切り替え | 戻し先を自動で設定した | 切断時の出力を『スピーカー』に設定しました（メニューで変更できます） |
| 警告 | 戻し先が未設定で切り替えなかった | ⚠ 切断時の出力が未設定です |
| 警告 | 戻し先が見つからず切り替えなかった | ⚠ 戻し先のデバイスが見つかりません |
| 警告 | 既定デバイスの設定が失敗した（API がエラーを返した） | ⚠ 出力を切り替えられませんでした |
| 警告 | 接続時の出力が未設定で、ドングルの Game デバイスも見つからず切り替えなかった | ⚠ INZONE Buds の出力デバイスが見つかりません |
| バッテリー | 左右のイヤホンの残量が低下した | 🔋 イヤホンの残量が少なくなっています（L 5% / R 4%） |

- 文面のデバイス名は、再生デバイスの一覧にある現在の名前を入れる。接続時の出力を利用者が選べるため、「INZONE Buds」と固定しない
- 戻し先が見つからない警告は、接続時の出力が見つからない場合にも同じ文面を使う
- バルーンの種類は、警告が `NIIF_WARNING`、それ以外が `NIIF_INFO`。タイトルは「INZONE Buds」

次の場面では通知しない。

- 接続中に利用者が手動で出力を変えていたため、切断時に切り替えなかった
- 状態が不明（起動直後、ドングル未検出）
- ドングルの抜き差し（トレイアイコンの表示だけで示す）

#### バッテリー低下通知

- **対象は左右のイヤホンだけ**。ケースは机の上で充電されたまま使われることが多く、通知の必要性が低いため
- **しきい値**：`low_battery_threshold`（既定 5%）以下になったら通知する
- **繰り返し通知しない仕組み**：左右それぞれに「通知済み」フラグを持たせ、ヒステリシスで解除する

```
  残量 ≤ しきい値 かつ 未通知  → 通知して「通知済み」にする
  残量 ≥ しきい値 + 10%       → 「通知済み」を解除する（充電されたとみなす）
```

  - 解除の基準をしきい値より 10% 上にするのは、5% と 6% の間を値が行き来しても再通知しないため
  - フラグはイヤホンが切断されても保持する。ケースに一瞬戻して出し直しただけでは、残量が回復していないので再通知しない
  - 残量が不明（`0xFF`）のレポートは無視し、フラグを変えない
  - フラグはメモリ上だけに持つ。アプリを起動し直したとき、残量がしきい値以下なら 1 回通知する
- 左右が同時にしきい値以下になった場合（同じレポートで両方が条件を満たした場合）は、1 つの通知にまとめる。文面にはしきい値以下になった側だけを入れる（例：`L 5%`）
- 通知がオフのときもフラグは更新する。オンに戻した直後に、前から低かった残量で通知が出るのを避けるため
- 状態機械と同じく、残量と現在のフラグを受け取って通知の要否と新しいフラグを返す純粋関数にして、単体テストを書く

### 4.6 設定

- 保存先：`%APPDATA%\inzone-buds-switcher\config.json`
- 例：

```json
{
  "auto_switch": true,
  "connected_device": { "id": "{0.0.0.00000000}.{...}", "name": "INZONE Buds - Game" },
  "disconnected_device": { "id": "{0.0.0.00000000}.{...}", "name": "スピーカー (Realtek ...)" },
  "switch_communications": false,
  "notify_switch": true,
  "notify_battery": true,
  "debounce_ms": 1500,
  "low_battery_threshold": 5
}
```

- `connected_device` が未設定なら、ドングルのデバイスのうち「Game」の方を自動で選ぶ
- `disconnected_device` は未設定（`null`）で始まり、[4.3](#切断時の戻し先) の規則で初期値が入る
- ファイルがなければ既定値で動く。ファイルは設定を保存するときに作る
- 欠けている項目は既定値を使い、知らない項目は無視する。先頭の BOM は読み飛ばす（メモ帳が付けることがある）
- JSON として読めない、または値の型が違うときは、警告をログに出し、ファイルを `config.json.bad` に名前を変えて退避し、既定値で動く。そのまま既定値で上書き保存すると、利用者が書いた内容が黙って消えるため
- 保存は一時ファイル（`config.json.tmp`）に書いてから置き換える。書き込みの途中で落ちても、壊れたファイルを残さないため

### 4.7 その他

- **単一インスタンス**：トレイとして起動するときだけ、名前付きミューテックス `Local\inzone-buds-switcher` で二重起動を防ぐ（`probe` などのサブコマンドは対象外）
  - `Local\` はログオンセッション単位。同じ PC の別ユーザーはそれぞれ 1 つ起動できる
  - 2 つ目はログに記録して、ダイアログを出さず終了コード 0 で静かに終わる。スタートアップとの重複など日常的に起こるため
- **スタートアップ**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の値 `inzone-buds-switcher` に、引用符で囲んだ exe のパスを書く（管理者権限は不要）
  - メニューの印は値の有無で決め、メニューを開くたびにレジストリから読む。exe を移動して古いパスが残っていても、メニューで外せるようにするため
  - 有効にするときは、実行中の exe のパスで上書きする
  - 設定ファイルの項目ではないので、`config.json` には持たない
- **ログ**：トレイとして起動したときだけ `%LOCALAPPDATA%\inzone-buds-switcher\logs\inzone-buds-switcher.<日付>.log` にも書く（標準エラーへの出力は残す）。サブコマンドは標準エラーだけ
  - 日次ローテーションで 14 ファイルまで残し、古いものから消す。2 週間分あれば不具合の報告に足り、容量も小さいため
  - 既定は info。`RUST_LOG` で変えられ、HID の生レポートは debug レベルで出す（解析・不具合報告用）
  - ログフォルダを作れないときは警告を出して標準エラーだけで動く
  - メニューの「ログフォルダを開く」はフォルダがなければ作ってから開く
- **INZONE Hub との共存**：HID は共有モードで開き、INZONE Hub が起動していても動作するようにする

## 5. 使用するクレート

| 用途 | クレート |
|---|---|
| HID | `windows`（cfgmgr32 / hid.dll を直接呼ぶ。理由は [4.1](#41-接続切断の検知hid)） |
| Win32 / COM（Core Audio、トレイ、レジストリ、ミューテックス） | `windows` |
| トレイアイコン・メニュー | `windows`（`Shell_NotifyIconW`、`CreatePopupMenu` / `TrackPopupMenu` を直接呼ぶ） |
| 設定 | `serde`, `serde_json` |
| ログ | `tracing`, `tracing-subscriber`, `tracing-appender` |
| エラー処理 | `anyhow` |
| exe へのアイコン埋め込み | `embed-resource` または `winresource` |

トレイに `tray-icon` / `muda` は使わない。通知（[4.5](#45-通知)）は同じトレイアイコンに `NIF_INFO` でバルーンを出すが、`tray-icon` はこれを公開していないため。依存も増やさずに済む。

`IPolicyConfig` は `windows` クレートに含まれないので、`windows::core::interface` マクロで自前定義する。

## 6. 配布

- `#![windows_subsystem = "windows"]` でコンソールを出さない
- `.cargo/config.toml` に `-C target-feature=+crt-static` を設定し、VC++ ランタイムなしで動かす
- `cargo build --release` で生成した exe 1 つを GitHub Releases に zip で置く
- GitHub Actions（`windows-latest`）でタグを push したら自動ビルドする
- exe はコード署名しない。そのため初回起動時に SmartScreen の警告が出るので、README で回避手順（「詳細情報」→「実行」）を案内する

## 7. 開発用サブコマンド

リリース版にも含め、実機の調査や不具合報告に使う。

| コマンド | 内容 |
|---|---|
| `probe` | ドングルの HID レポートを生のまま出力する |
| `watch` | HID 監視スレッドのイベント（ドングルの検出/切断、接続状態、バッテリー）をログに出す |
| `list` | 再生デバイスの一覧（エンドポイント ID、表示名、ドングルの種別）を出力する。既定のデバイスには `*` が付く |
| `set <id> [--communications]` | 既定の再生デバイスを設定する（eConsole と eMultimedia。`--communications` で eCommunications も） |

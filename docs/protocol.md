# INZONE Buds ドングル HID プロトコルメモ

> ⚠ ここに書いた内容は、下記の既存 OSS のソースや README から読み取ったもので、**まだ実機で確認していない**。
> 実機で確認できた内容は、このファイルに反映する。

## デバイス

| 項目 | 値 |
|---|---|
| Vendor ID | `0x054C`（Sony） |
| Product ID | `0x0EC2`（INZONE Buds USB トランシーバー） |
| ベンダー定義 HID | interface `5`、usage_page `0xFF04`、usage `0x0001`（battery-tray の記載） |
| レポート ID | `0x02` |
| レポート長 | 64 バイト |

トランシーバーのスライドスイッチは **PC** 側にしておくこと。

## 1. 状態レポート（自発送信）— 接続/切断の検知に使う

出典：buds-watcher `src/device.py`

ドングルは接続状態が変わると、このレポートを送ってくる（`read` で待っていれば届く）。

| オフセット | 値 | 意味 |
|---|---|---|
| `[8]` | `0x12` | レポート種別 |
| `[9]` | `0x01` | 状態レポート |
| `[13]` | 0 / 非0 | 左イヤホンの接続状態 |
| `[14]` | 0 / 非0 | 右イヤホンの接続状態 |

最小長は 15 バイト。

## 2. バッテリーレポート

### 2a. 自発送信（buds-watcher）

| オフセット | 値 | 意味 |
|---|---|---|
| `[8]` | `0x14` | レポート種別 |
| `[9]` | `0x04` | バッテリー |
| `[14]` | 0–100 / `0xFF` | 左（%） / 不明 |
| `[16]` | 0–100 / `0xFF` | 右（%） / 不明 |

### 2b. 能動的な問い合わせ（inzone-buds-battery-tray `docs/protocol.md`）

INZONE Hub と同じ方法で問い合わせる。

- 要求：64 バイトの出力レポート（Windows では `WriteFile` / hidapi の `write`）

| オフセット | 値 |
|---|---|
| `[0]` | `0x02`（レポート ID） |
| `[8]` | `0x41`（コマンド） |
| `[9]` | `0x04`（バッテリー） |
| `[10]` | `0x01` |
| `[11]` | シーケンス番号 |
| `[13]` | `0x9B + subcommand + sequence`（チェックサムのような値） |

- 応答：割り込み IN（エンドポイント `0x83`）

| オフセット | 値 |
|---|---|
| `[8]` | `0x14` |
| `[9]` | `0x04` |
| `[10]` | `0x10` |
| `[11]` | 要求と同じシーケンス番号 |
| `[14]` (`0x0E`) | 左（%）、`0xFF` は利用不可 |
| `[16]` (`0x10`) | 右（%）、`0xFF` は利用不可 |
| `[18]` (`0x12`) | ケース（%）、`0xFF` は利用不可 |

- 既知の制限：**両耳ともケース内だと、ドングルが応答しないことがある**

### 2a と 2b の関係（要確認）

左右のオフセット（14 / 16）が一致しているので、同じ種類のレポートと思われる。2a は問い合わせへの応答を受け取っているだけの可能性もある。
